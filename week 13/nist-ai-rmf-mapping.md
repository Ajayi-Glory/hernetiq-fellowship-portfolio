# Level 5 — NIST AI RMF Mapping

## LegalBot Municipal

This mapping applies the NIST AI Risk Management Framework (AI RMF) to the LegalBot Municipal security incident in Level 5. It examines how the organisation should govern, identify, assess and manage risks associated with the AI agent.

| NIST AI RMF Function | My Finding |
|---|---|
| **GOVERN** | Organisations should establish clear security policies, responsibilities and approval procedures before deploying an AI agent. In this case, LegalBot had permission to approve and dismiss municipal cases without requiring human review. This level of authority was unnecessary for its normal support functions. The organisation should apply the principle of least privilege, limit the agent's decision-making powers and require human approval before sensitive case decisions are finalised. Responsibility for monitoring the system should also be clearly assigned. |
| **MAP** | Before deployment, the organisation should understand the agent's purpose, permissions, users and potential impact on affected individuals. LegalBot handles citizens' case comments and supports municipal case processing. However, its configuration included `CAN_FINALIZE_DISMISSAL = True` and `REQUIRE_HUMAN_APPROVAL = False`. A citizen comment was used to attempt a goal hijack. This demonstrates how untrusted input could influence an agent with excessive permissions. If successful, the attack could affect municipal records, citizens' cases and the staff responsible for reviewing them. |
| **MEASURE** | The organisation should evaluate the agent's security and reliability before deployment and throughout its operation. Testing should include malicious citizen comments, attempts to redirect the agent from its intended task and checks for unauthorised actions. The agent's configuration should also be reviewed for excessive permissions and missing approval controls. The assessment should establish whether the agent can be manipulated, whether it can perform sensitive actions without authorisation and what harm could result. Identified risks should then be prioritised according to their severity. |
| **MANAGE** | The organisation should take corrective action to reduce the identified risks and verify that the controls work as intended. The immediate response should be to disable the agent's standing dismissal authority by setting `CAN_FINALIZE_DISMISSAL = False` and requiring human approval through `REQUIRE_HUMAN_APPROVAL = True`. Citizen comments should be treated as untrusted input and sanitised using `SANITIZE_CITIZEN_INPUT = True`. Agent activities should also be recorded using `LOG_AGENT_ACTIONS = True` to support monitoring, investigation and accountability. Additional safeguards, such as input validation and approval checks, should be introduced. Finally, the system should be tested again to confirm that malicious instructions cannot trigger unauthorised case decisions. |
